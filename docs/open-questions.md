# Open questions

These questions are intentionally unresolved. None blocks preparation of the documentation, but the blocking items must be resolved before the relevant phase begins.

## Blocking before repository setup

- Will the GitHub repository be public or private?
- Which open-source license, if any, should apply?
- Is `Wayfare` the final product name or only a working name?

## Blocking before capture implementation

- Which free backend can be created without a payment card at the time of implementation?
- How will the Apple Shortcut authenticate without embedding a long-lived secret that is difficult to revoke?
- What maximum screenshot size preserves useful evidence within free storage limits?
- Which kinds of private social content may be stored, and for how long?

## Blocking before partner access

- Should both administrators see all notes, or can a note be private to its author?
- Should both administrators have equal authority to delete data and change account settings?
- Which relationship label should be the default: Partner, Girlfriend, or another value?

## Non-blocking product questions

- Is a five-point rating enough, or should interest be expressed as yes, maybe, and no?
- Should rejected places remain searchable?
- What makes a price stale: a fixed period, category-specific period, or manual flag?
- Should distance initially mean straight-line distance or road distance?
- Which Bangladesh-specific categories and price units deserve first-class support?
- Should contact actions distinguish phone, WhatsApp, Messenger, website, and booking page?

## Research questions

- What exactly does each target iPhone app provide to the Share Sheet?
- How often are price and contact details embedded only in an image?
- Can useful location confidence be achieved without a paid geocoder?
- Does a couple match score aid decisions or merely decorate individual ratings?
- Does accumulated visit history improve planning enough to justify an import workflow?
